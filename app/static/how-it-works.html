How it works

The recorder, the rules and the known faults · as of 2026-10-13

SplitTime records the telemetry Forza Horizon 6 sends while you drive, works out where each lap or run starts and ends, and compares drivers' best times. The game sends physics and a few clocks. It does not send the track name, the event type, the official result or whether a lap was valid. Everything on this site beyond the raw numbers is inferred, and this page says how, and where the inference is currently wrong.

1. The pieces

Two processes share one SQLite file. The collector must stay up, because a packet that arrives while it is down is lost for good. The website can be rebuilt at any time.

  • Lossless by design. Laps, routes and flags are an index over the stored packets. Deleting the index and rebuilding it from the packets gives the same answer, or a better one after a fix.
  • One writer at a time. The collector waits at most 0.25 s for the database, then keeps its frames in memory (up to 3600) and retries on the next flush. A reprocess or import on the website is refused while any session is recording.

3. Sessions

A session is one continuous attempt at one event. Restarting an event makes a new session.

Attempts

Every started event is one attempt, however short. A session that ends with a timed lap or run is a finished attempt. One that ends without is given up: its packets go, but one small row stays with the driver, the car, where it started and how far it got. "Started" means a race from a grid, or a lap-timed event, whose odometer left the line. The route of a given-up attempt is worked out from its start position: the one recorded route that starts within 120 m, else the one catalogue course, else "Unknown route".

4. Laps on a circuit

Where the game runs its lap fields, the recorder trusts them:

  • LapNumber goes up → the open lap is closed with the game's own LastLap time, and the next lap opens.
  • LastLap changes while LapNumber stays put → the final lap of a race. The game stops counting at the finish line.
  • The lap clock starts counting after sitting at zero → the lap is re-anchored there (free-roam time attack).
  • In Rivals the lap clock runs during the approach and resets at the start line. That reset is treated as the launch, not as a rewind.

While a lap is open the recorder keeps a trace of (distance into lap, elapsed time). The live delta is the current lap's time at this distance minus the session-best lap's time at the same distance. Comparing by distance, not by clock, is what makes two laps comparable corner by corner.

5. Finishing an event

This is the hardest part and the source of most faults. The game ends an event without incrementing LapNumber, and a sprint, drag or touge run never has a lap boundary at all. The recorder looks for a finish in this order. Rungs 1 to 3 are checked on every packet; rungs 4 to 6 only when the stream has stopped.

Where the clock starts for a run

"Launch" is the packet where the odometer first reaches 1.0. The code assumes that is the moment the lights go out on the grid. On the gridded sprints and drag runs recorded so far, the grid sits at a negative odometer reading (−70.8 on one sprint), so the odometer reaches 1.0 at the start line, not on the grid. Recorded run times are therefore line-to-line. See fault F5.

6. Events with no lap clock (World Time Attack)

Some events send no lap fields at all. Laps are then found from position alone.

7. Lap flags

Flags can be corrected by hand on the Analysis page. Corrections are stored separately, keyed by time, and survive a reprocess.

8. Routes and their names

The first timed lap of a session produces a fingerprint: start position, length on the odometer, and the width and depth of the ground covered. It is matched against known routes.

Because the odometer is normalised to about 5950 on every course, the length test separates nothing among completed runs. Start position and span do the work. The length test matters in one case only: a run that stopped short. Such a run is no longer timed (faults F3 and F4), so it no longer reaches this step.

9. Sittings

Restarting an event creates a new session, so an evening on one sprint arrives as many one-run sessions. When a session closes, finished sessions with the same driver, route and car, each starting within 2 hours of the one before, are grouped into a sitting. A sitting is an index entry: no lap or packet is moved. A session someone takes out of a sitting is never regrouped. Bests never depended on this; it only tidies the lists.

10. Which time counts as a best

This is the closest available match to the game's Rivals rule. The game's own verdict is not in the packet, and leaving the track is not detected at all.

13. What might be fixed

  1. Done: require the distance before calling it a finish (F3, F4). A gridded run is timed only when the odometer has reached the full-route reading (98.5% of 5950), in rungs 2, 3 and 5. A run that stops short keeps its packets but gets no time and no route, and a session with no timed run is discarded like any abandoned event. Old recordings change only when they are reprocessed. Still open: the 5950 figure is measured, not documented, and the test is not applied to events with no lap clock, whose odometer at a finish has not been measured.
  2. Settle the clock origin (F5). Compare one result-screen time with the recording. If the game counts from the grid, time runs from the first packet where the race clock moves (or speed leaves zero) and reprocess the sprints. The replay's alignment follows the same clock.
  3. Name what the catalogue lacks (F6). Rename the route on the Analysis page, and add the entry to the catalogue so a fresh install recognises it.
  4. Capture each event type once (F7, F8). With "keep discarded" switched on, one drift event, one Rivals run and one race on the same route give the data needed to tell them apart, or to show that they cannot be told apart from telemetry.
  5. Approximate off-track (F9). The packet's driving-line field saturates at ±127 when the car is far from the course. A sustained saturation could set an "off course" flag. It would be a second approximation of the game's rule, not the rule.
  6. Give laps a stable identity (F10). Address a lap by session and time anchor, as manual edits already are, so links survive a reprocess.
  7. Statistics from packets. Top speed, air time and time on throttle need a pass over the stored packets, cached per lap.
